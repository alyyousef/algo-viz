In programming theory, there is a strict mathematical difference between a **Statement** and an **Expression**.
- A **Statement** is an instruction that *does* something (e.g., `if (x > 5)`). It does not mathematically return a value.
- An **Expression** is a mathematical phrase that can be *evaluated* to produce a value (e.g., `x + 5`).

## 1. Expression Evaluation
When the compiler encounters an expression like `(A + B) * C`, it mathematically parses it into an **Abstract Syntax Tree (AST)**. The CPU must evaluate the mathematical leaves of the tree first. It loads `A` into a register, loads `B` into a register, uses the ALU to add them, and replaces that sub-tree with the new value, recursively continuing until the entire expression collapses into a single mathematical value.

## 2. Expression-Oriented Languages
In imperative languages (C, Java), `if` is a Statement. You cannot write `let x = if (true) { 1 } else { 2 }`.
In functional and modern systems languages (Rust, Scala, Kotlin), almost everything is an **Expression**. An `if` block mathematically evaluates and returns the value of its last line. This prevents developers from having to declare uninitialized variables (`let x;`) and mutating them inside `if` blocks, enforcing safer, mathematically pure code.
