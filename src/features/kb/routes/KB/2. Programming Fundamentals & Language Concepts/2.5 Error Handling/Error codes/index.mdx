Before modern Exceptions were invented, Error Codes were the only mathematical way a function could communicate failure back to the caller.

## 1. The Integer Contract
Because a C function can only mathematically return one value, if it needs to return data, how does it return an error?
Standard convention dictates that functions return `0` for mathematical success, and a negative integer (e.g., `-1`) for failure. If the function needs to return actual data, it returns a Memory Pointer. If the pointer is mathematically exactly `0x0` (Null), it indicates failure.

## 2. The errno Global
If a function returns `-1`, how do you know *why* it failed?
Operating Systems (like POSIX/Linux) utilize a massive global variable named `errno`. If a system call fails, the OS mathematically writes a specific Error Code into `errno` (e.g., `2` for "File Not Found", `13` for "Permission Denied").
The caller must instantly check the `errno` global variable. This is mathematically dangerous in multi-threaded environments, because if Thread B triggers an error exactly one millisecond after Thread A, Thread B will overwrite `errno`, and Thread A will read the wrong mathematical error code.
