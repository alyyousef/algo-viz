Tony Hoare famously called the invention of the `null` reference the "Billion Dollar Mistake" due to the catastrophic number of crashes (NullPointerExceptions) it has caused in software history.

## 1. The Defensive Coding Nightmare
If a method returns a `Logger` object, but logging is disabled, the method returns `null`.
Now, every single place in the codebase that uses the logger must mathematically execute: `if (logger != null) { logger.log("msg"); }`. This pollutes the business logic with endless defensive checks.

## 2. The Neutral Implementation
The Null Object pattern solves this by providing a polymorphic alternative to `null`.
You create a `NullLogger` class that mathematically implements the `ILogger` interface. Its `log()` method is completely empty; it does absolutely nothing.
When logging is disabled, the method returns the `NullLogger` object instead of `null`.
The client code blindly executes `logger.log("msg")`. The code mathematically succeeds without crashing, entirely eliminating the need for the `if (logger != null)` check and cleaning up the architecture.
