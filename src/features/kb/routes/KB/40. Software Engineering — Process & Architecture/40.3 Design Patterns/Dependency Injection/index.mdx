If a `UserService` class needs to save data, and it executes `Database db = new MySQLDatabase();` internally, it is mathematically tightly coupled to MySQL. You cannot test this class without spinning up a physical MySQL server.

## 1. Injecting via Constructor
Dependency Injection solves this by mathematically forbidding the use of the `new` keyword for dependencies.
Instead, the `UserService` demands its dependency via its constructor:
```java
public class UserService {
    private IDatabase db;
    public UserService(IDatabase db) { this.db = db; }
}
```
The class is now perfectly mathematically isolated. When running in production, the DI Framework (like Spring or NestJS) automatically instantiates the real `MySQLDatabase` and injects it into the constructor.

## 2. The Power of Mocks
Because the class only asks for an `IDatabase` interface, when a developer writes a Unit Test, they instantiate a `MockDatabase` (which just saves data to a temporary RAM array) and mathematically inject it into the `UserService` constructor. The code compiles, runs in 1 millisecond, and tests the core business logic perfectly without ever touching a real database.
