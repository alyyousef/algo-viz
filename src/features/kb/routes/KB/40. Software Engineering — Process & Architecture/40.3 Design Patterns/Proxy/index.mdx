If you have a massive `HighResImage` object that takes 5 seconds to load from the hard drive, and a user scrolls through a gallery of 1,000 images, instantiating all 1,000 objects will mathematically freeze the application.

## 1. The Surrogate Object
The Proxy pattern solves this by putting a fake "bodyguard" object in front of the real object.
Both the `HighResImage` and the `ImageProxy` mathematically implement the exact same `IImage` interface (which has a `display()` method).
When the gallery loads, it instantiates 1,000 `ImageProxy` objects. This takes 1 millisecond, because the Proxy mathematically contains no image data; it just contains the file path.

## 2. Lazy Initialization
When the user actually scrolls to Image #42, the gallery calls `proxy.display()`.
The Proxy mathematically intercepts the call. It checks if the real `HighResImage` exists in RAM. It doesn't. So, the Proxy pauses, instantiates the heavy real object, loads the 5MB file from disk, and then mathematically forwards the `display()` call to the real object. The client code is completely ignorant that it was talking to a surrogate.
