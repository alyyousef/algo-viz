If you have a mobile app downloaded by 1 million users, and you change the API response from `{ "name": "Alice" }` to `{ "firstName": "Alice", "lastName": "Smith" }`, the mobile app will crash instantly because it is mathematically expecting the `name` key.

## 1. The Necessity of Versioning
You mathematically cannot force 1 million users to update their app on the same day. Therefore, the server must support *both* the old and the new mathematical structures simultaneously. This is achieved via Versioning.

## 2. Versioning Strategies
There are three standard mathematical ways to route the request:
- **URI Routing**: The most common. The client explicitly requests `https://api.com/v1/users` or `https://api.com/v2/users`. The load balancer routes the traffic to different controllers.
- **Header Versioning**: The URI remains clean (`/users`), but the client sends a custom HTTP header: `X-API-Version: 2`.
- **Accept Header (Content Negotiation)**: The most mathematically RESTful, but hardest to implement. The client specifies the exact mathematical shape it expects: `Accept: application/vnd.company.user.v2+json`.
