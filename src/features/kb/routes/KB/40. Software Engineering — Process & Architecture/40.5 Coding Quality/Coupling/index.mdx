If Cohesion measures how well a class is structured internally, **Coupling** measures how mathematically entangled it is externally.

## 1. Tight Coupling (The Danger)
If Class A instantiates Class B directly using the `new` keyword, Class A is mathematically **Tightly Coupled** to Class B.
```java
class OrderService {
    void process() {
        MySQLDatabase db = new MySQLDatabase(); // Tight Coupling!
        db.save();
    }
}
```
If the company migrates to MongoDB, the developer must open the `OrderService` file and physically rewrite the business logic to remove MySQL. The core business rules are held mathematically hostage by the database infrastructure.

## 2. Loose Coupling (The Solution)
Loose Coupling is achieved through Interfaces and Dependency Injection.
```java
class OrderService {
    private IDatabase db; // Loose Coupling
    public OrderService(IDatabase db) { this.db = db; }
}
```
Now, `OrderService` is mathematically completely ignorant of whether the database is MySQL or Mongo. You can completely delete the MySQL library from the codebase, and the `OrderService` file does not need a single line changed. This provides ultimate architectural flexibility.
