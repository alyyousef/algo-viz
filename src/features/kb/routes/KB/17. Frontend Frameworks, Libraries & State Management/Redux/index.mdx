Redux is an open-source JavaScript library for managing and centralizing application state. It is most commonly used with libraries such as React or Angular for building user interfaces. Similar to (and inspired by) Facebook's Flux architecture, it was created by Dan Abramov and Andrew Clark.

<Callout icon="error" title="Modern Redux: Redux Toolkit (RTK)">
  Historically, Redux was infamous for requiring massive amounts of boilerplate code (constants, actions, reducers). **Redux Toolkit (RTK)** is now the official, recommended approach, which massively simplifies Redux by wrapping it in highly efficient abstractions and integrating Immer.js for immutable updates.
</Callout>

## Data Flow Architecture (One-Way)

Redux enforces strict unidirectional data flow. This makes state changes highly predictable and easy to trace.

## Redux Toolkit (RTK) Example

RTK introduces `createSlice`, which automatically generates action creators and action types based on the reducer functions you define. It also uses Immer under the hood, allowing you to write "mutative" code that actually produces safe, immutable updates.

```text
import { createSlice, configureStore } from '@reduxjs/toolkit'

// 1. Create a Slice (Combines state, reducers, and actions)
const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: state => {
      // Immer allows us to "mutate" the state directly here
      state.value += 1
    },
    decrement: state => {
      state.value -= 1
    },
    incrementByAmount: (state, action) => {
      state.value += action.payload
    }
  }
})

// 2. Export Actions
export const { increment, decrement, incrementByAmount } = counterSlice.actions

// 3. Configure Store
export const store = configureStore({
  reducer: {
    counter: counterSlice.reducer
  }
})
```

## Redux vs. Context API

A common question is whether the native React Context API replaces Redux.
- **Context API:** Great for low-frequency updates (e.g., Theme, Locale, User Auth). Terribly inefficient for high-frequency updates, as any state change re-renders all consumers.
- **Redux:** Excellent for complex, high-frequency, application-wide state. Components specifically subscribe only to the slices of state they care about, optimizing rendering performance significantly.
