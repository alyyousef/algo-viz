**Block Volumes** are iSCSI (or paravirtualized) disks you attach to OCI Compute. Size and **VPUs** (volume performance units) set IOPS and throughput. Volumes live in an AD (or as regional where offered). Boot volumes are the same product with a special role.

## 1. Deep Dive and Mechanics

**Attach types.** Paravirtualized is simpler. iSCSI needs the IQN and sometimes iscsiadm in the guest. Multipath and consistent device names matter for databases.

**Performance.** Balanced, higher, and ultra tiers map to VPU/GB. Burst is not a plan for a 24/7 OLTP redo disk. Ultra is for the few workloads that can saturate it.

**Data protection.** Point-in-time backups to object storage, clones for refresh, and volume groups for crash-consistent sets (DB + redo). Cross-AD / cross-region backup copy is the DR path.

**Resize.** Online expand is common; shrink is not. Filesystem grow is a separate guest step you will forget once.

<Callout icon="error" title="Delete instance, keep the volume">
The console checkbox that deletes the boot volume with the instance is how people lose a disk. Terraform `preserve` settings should be explicit.
</Callout>

## 2. Mathematical / Theoretical Foundation

IOPS ≈ f(VPU, size). Tiny volumes cannot hit the IOPS you mentally associated with the tier. Size up or raise VPUs; measure with fio, not hope.

Latency is network-attached. A chatty fsync-per-row app on a cheap volume will look like "OCI is slow."

## 3. Real-World Implementation

```bash
oci bv volume create --compartment-id $COMP \
  --availability-domain "$AD" \
  --display-name data-1 --size-in-gbs 256 \
  --vpus-per-gb 10

oci compute volume-attachment attach-iscsi \
  --instance-id $INST --volume-id $VOL
```

Then run the attach commands in the guest and mount by UUID in fstab.

## 5. Interview Prep

**Q: Boot volume vs block volume?**
**A:** Same service. Boot is the OS disk created from an image. Data volumes you attach extra.

**Q: How do you move a volume to another AD?**
**A:** Backup/restore or clone into the target AD. You do not hot-plug across ADs like a local drive.

**Q: Volume group vs single backups?**
**A:** Groups snapshot a set at one consistent moment. Use them for multi-disk databases.

## 6. Production Use Cases

- Database data and redo on separate volumes with matching VPU.
- Clone a prod volume into a lower compartment for a refresh.
- Scheduled backups copied to a second region.

<Callout icon="tip" title="Mount by UUID">
Device names rotate after attach order changes. fstab by UUID survives the next incident.
</Callout>
