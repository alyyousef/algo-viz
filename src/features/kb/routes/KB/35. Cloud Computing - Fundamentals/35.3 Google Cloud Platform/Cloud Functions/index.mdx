**Cloud Functions** runs a single entrypoint per deploy. **1st gen** is the original functions product. **2nd gen** is Cloud Run plus Eventarc: longer timeouts, concurrency, and more event sources. Triggers are HTTP or events (Pub/Sub, Storage, Firestore, Audit Logs). If the unit is already a container, skip ahead to Cloud Run.

## 1. Deep Dive and Mechanics

**Gen 2.** Builds an image, deploys a Cloud Run service, wires Eventarc. You get Cloud Run knobs: min/max instances, CPU always allocated, VPC connector or Direct VPC egress.

**Triggers.** HTTP is an HTTPS endpoint (put IAP or an LB in front). Eventarc uses CloudEvents. Storage finalize is the usual thumbnail story.

**Identity.** Per-function service account. Do not use the default compute SA. Eventarc needs a trigger SA that can invoke the function.

**Cold start.** Language + package size + min instances. Gen 2 concurrency means one instance can handle many requests — different from 1st gen’s one-request model.

**Source vs image.** You can still deploy source; Cloud Build builds it. Reproducible deploys pin the build.

<Callout icon="warning" title="1st gen vs 2nd gen is not a rename">
Event payload shapes, IAM, and networking differ. Migrating is a project. New work should be 2nd gen unless a 1st gen-only trigger still blocks you.
</Callout>

## 2. Mathematical / Theoretical Foundation

Billing is invocation count + compute time + egress (and Cloud Run’s model for gen 2). A chatty Pub/Sub function at 1 ms still pays per message.

Eventarc delivery is at-least-once. Idempotency keys on Storage object generation or Pub/Sub message id.

## 5. Interview Prep

**Q: Functions vs Cloud Run?**
**A:** Functions if you want a source-based entrypoint and a trigger catalog. Cloud Run if you already have a Dockerfile or need multiple routes in one service. Gen 2 blurs this on purpose.

**Q: How do you stop a retry storm?**
**A:** Idempotent writes, max retry on the trigger, and an alert on error rate. Eventarc will retry.

**Q: Why VPC connector?**
**A:** To reach private IPs (Memorystore, internal GCE). Direct VPC egress on Cloud Run is the newer path — prefer it when available.

## 6. Production Use Cases

- Image pipeline: Storage → Function → Storage + Pub/Sub.
- Audit log sink → Function that pages on `SetIamPolicy`.
- HTTP webhooks with min instances = 1 for a partner SLA.

<Callout icon="tip" title="One function, one trigger">
A mega-function with an internal switch on event type is a monolith with worse tooling. Split deployables so you can scale and IAM them apart.
</Callout>
