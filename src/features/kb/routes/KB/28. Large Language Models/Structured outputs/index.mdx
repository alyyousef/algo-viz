For consumers, an AI chatbot is useful if it outputs a nicely formatted English essay. For software engineers, an English essay is completely useless. 

If you are building an app that uses an LLM to extract names and ages from a PDF, your backend code (e.g., Node.js or Python) will crash if the LLM replies: *"Here are the names you requested: John is 25..."*
Your code needs the LLM to reply with a perfect, parsable **Structured Output**, such as:
`{ "users": [ { "name": "John", "age": 25 } ] }`

Historically, forcing an LLM to output perfect JSON was the hardest part of AI engineering. 

## The Evolution of Structured Outputs

### Phase 1: Prompt Engineering (The Dark Ages)
In 2021, developers had to beg the AI in the system prompt: *"You must ONLY output valid JSON. Do not include markdown. Do not say 'Here is your JSON'. Just output the JSON."*
Even with strict prompting, the model would randomly fail 10% of the time, outputting a missing comma or a trailing string, crashing production servers.

### Phase 2: JSON Mode (Fine-Tuning)
Companies like OpenAI realized this was a massive pain point. They released **JSON Mode**.
They took their Base Models and fine-tuned them on millions of examples of valid JSON. When a developer toggles `response_format: { type: "json_object" }` in the API, the model is mathematically biased to output JSON. While highly reliable, the model still didn't guarantee that it would follow the exact *schema* (keys and data types) the developer wanted.

### Phase 3: Structured Outputs / Constrained Decoding (Current State-of-the-Art)
In 2024, the industry moved from "hoping" the model outputs valid JSON to **mathematically forcing it**. This is called **Constrained Decoding** (used in OpenAI's Structured Outputs API, or open-source libraries like Outlines).

When the developer provides a JSON Schema (e.g., *"The output must have a key called 'age' and it must be an integer"*), the API alters the internal Tokenizer of the LLM. 
When the LLM is about to predict the next token, the software looks at the probability distribution. If the LLM wants to output the word *"Hello"*, but the JSON Schema requires an integer, the software brutally overrides the LLM, setting the probability of *"Hello"* to 0%, and forcing the model to pick a number.

<Callout icon="check-double" title="100% Reliability">
Constrained Decoding guarantees **100% structural reliability**. Because the generation is constrained at the token-selection level, it is mathematically impossible for the LLM to output a missing bracket, a typo in a key name, or a string when an integer is required. This technology is what enables reliable, autonomous AI Agents to exist.
</Callout>
