In an autoregressive decoder model, generating the 100th token requires calculating attention scores against the previous 99 tokens. Generating the 101th token requires calculating against the previous 100 tokens.

Without optimization, the model would re-calculate the mathematical Key (K) and Value (V) matrices for all preceding tokens at every single step, leading to catastrophic $O(N^2)$ computational waste.


<Callout icon="success" title="The Solution">


  The **KV Cache** solves this by saving the computed K and V matrices for past tokens in GPU memory. When generating the next token, the model only computes the K and V for the *new* token, and appends it to the cache.


</Callout>


## The Memory Bottleneck

While KV Caching drastically reduces compute (FLOPs), it consumes a massive amount of VRAM.
