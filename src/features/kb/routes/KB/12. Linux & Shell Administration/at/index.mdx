While the famous `cron` utility is used to schedule scripts that run *repeatedly* (e.g., every Tuesday at 3 AM), the **`at`** command is designed to schedule a script to run exactly **one single time** in the future.

This is highly useful for sysadmins executing one-off maintenance tasks when they do not want to stay awake until midnight.

## Usage and Syntax

The `at` command reads from Standard Input. You specify the time, type the commands you want to run, and then press `Ctrl+D` to save the job.

```bash
$ at midnight
warning: commands will be executed using /bin/sh
at> systemctl restart nginx
at> <Ctrl+D>
job 3 at Wed Oct 18 00:00:00 2024
```

The time parser in `at` is incredibly flexible and understands human-readable syntax. You can type:
- `at 4:00 PM`
- `at now + 2 hours`
- `at 9:00 AM next friday`


<Callout icon="info" title="The atq and atrm Commands">


  Once a job is scheduled, the background `atd` daemon takes over.
  You can view all currently pending jobs by running the `atq` command.
  If you realize you made a mistake and want to cancel job #3 before midnight arrives, you simply run `atrm 3`.


</Callout>
