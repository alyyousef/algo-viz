When a compiled C program runs, it rarely executes entirely on its own code. It constantly relies on shared System Libraries (like `glibc`) to perform basic tasks like copying memory strings or calculating math.

**`ltrace`** is a deep diagnostic tool that attaches to a running process and prints exactly which library functions the program is calling in real-time.

## strace vs ltrace

It is critical to understand the difference between `strace` and `ltrace`:
- **`strace`** traces System Calls (the program talking directly to the Linux Kernel, like "open file" or "send network packet").
- **`ltrace`** traces Library Calls (the program talking to user-space C libraries, like `strlen()` or `malloc()`).


<Callout icon="success" title="Reverse Engineering and Hacking">


  `ltrace` is heavily used in cybersecurity Capture The Flag (CTF) events. If you are given a compiled, undocumented binary that asks for a secret password, you can run `ltrace ./binary`. When you type a fake password, `ltrace` will intercept the `strcmp(input, "SUPER_SECRET_123")` library call, instantly revealing the hardcoded password in plain text on your screen.


</Callout>


## Basic Usage
`ltrace ./my_program` will launch the program and flood your terminal with every C library function it executes, providing a massive window into how the black-box binary was programmed.
