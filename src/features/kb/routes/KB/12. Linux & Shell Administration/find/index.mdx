While `grep` searches *inside* files, the **find** command searches for the *files themselves* within the directory structure.

It is incredibly flexible. You can search by file name, creation date, modification date, file size, or permissions.

## Common Examples

**1. Find by Name:**
Find all `.config` files in the current directory and subdirectories.
```bash
find . -name "*.config"
```

**2. Find by Size:**
Find files larger than 100 Megabytes in the `/var/log` directory.
```bash
find /var/log -type f -size +100M
```

**3. Find by Modification Time:**
Find files modified in the last 7 days.
```bash
find /home/user -mtime -7
```

## Executing Commands on Found Files
The true power of `find` comes from the `-exec` flag. It allows you to run a command on every single file that matches your search criteria.

Find all files with a `.tmp` extension and immediately delete them:
```bash
find . -name "*.tmp" -exec rm {} \;
```
*(The `{}` is a placeholder for the found file's name, and the `\;` terminates the exec command).*

<Callout icon="warning" title="Efficiency">
If you are searching a massive file system, `find` can be slow because it actively crawls the disk. If you only need to search by filename, the `locate` command is often faster because it queries a pre-built background database (though that database might be hours out of date).
</Callout>
