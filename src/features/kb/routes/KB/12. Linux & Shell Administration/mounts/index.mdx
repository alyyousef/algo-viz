In Windows, if you plug in a USB drive, it automatically appears as the `E:` drive.
In Linux, the Filesystem Hierarchy Standard dictates there is only one single unified tree, starting at `/`.

To access data on a hard drive, you must use the **`mount`** command to graft the drive's filesystem onto an empty folder inside that tree (usually inside `/mnt` or `/media`).

## The Mount Command

If you plug in a new SSD, the Kernel will assign it a block device file (e.g., `/dev/sdb1`).
To make it usable, you create a directory and mount it:

```bash
sudo mkdir /mnt/database
sudo mount /dev/sdb1 /mnt/database
```

Now, any file you write into `/mnt/database` is physically written to the new SSD.


<Callout icon="success" title="Virtual Filesystems">


  `mount` is not just for physical hardware. Linux heavily relies on virtual, RAM-only filesystems.
  For example, `/proc` and `/sys` are actually fake filesystems dynamically generated by the Kernel in RAM. The `mount` command is used to attach these data structures to the FHS tree so humans can read them using standard text tools like `cat`.


</Callout>


## Unmounting (umount)
Before you unplug a USB drive, you must run **`umount /mnt/usb`**. This forces the Kernel to flush all pending, cached data from RAM physically onto the flash memory of the drive. If you unplug it without unmounting, data corruption is almost guaranteed.
