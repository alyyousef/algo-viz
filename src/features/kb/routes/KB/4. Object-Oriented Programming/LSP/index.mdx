Introduced by computer scientist Barbara Liskov in 1987, this principle mathematically defines what it actually means to create a subclass.

## 1. The Square-Rectangle Problem
The classic violation of LSP is the Square-Rectangle problem.
In mathematics, a Square is a Rectangle. So a developer makes `Square` inherit from `Rectangle`.
A `Rectangle` has methods `setWidth(w)` and `setHeight(h)`. But for a `Square` to remain a square, setting the width *must* automatically change the height to match.
If an external function expects a generic `Rectangle`, sets the width to 5, sets the height to 10, and mathematically calculates the area as 50, passing in a `Square` will break the function (the area will calculate as 100). The `Square` mathematically failed substitution.

## 2. Behavioral Subtyping
LSP dictates that a child class must honor the mathematical **Preconditions** and **Postconditions** of its parent.
If a parent method `process(String data)` promises to never return `null`, the child class overriding that method cannot suddenly start returning `null`. If it does, the substitution fails, the application mathematically throws a `NullPointerException`, and the inheritance tree is proven to be architecturally invalid.
