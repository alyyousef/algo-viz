In Object-Oriented Design, a `University` class *has a* `Professor` class. But the mathematical lifecycle of these two objects is loosely coupled.

## 1. The "Has-A" Relationship
Aggregation models a relationship where one class is a collection or container of other classes, but it does not mathematically own them.
```java
public class Department {
    // The Department aggregates Professors
    private List<Professor> professors;

    public Department(List<Professor> profs) {
        this.professors = profs;
    }
}
```
The `Department` object holds a list of `Professor` objects, but it did not create them.

## 2. Independent Lifecycles
The defining mathematical characteristic of Aggregation is the lifecycle independence.
If the university goes bankrupt and the `Department` object is mathematically destroyed (garbage collected) by the system, the `Professor` objects **do not die**. They still exist in memory and can be assigned to a different `Department` or a different `University` entirely. They are aggregated, not owned.
