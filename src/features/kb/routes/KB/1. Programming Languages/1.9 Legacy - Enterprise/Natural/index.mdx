**Natural** was created by Software AG in 1979 as one of the first commercially successful **Fourth-Generation Languages (4GLs)**.

To understand Natural, you must understand the distinction between language generations. 
- 1st Gen: Machine Code (0s and 1s)
- 2nd Gen: Assembly Language
- 3rd Gen: COBOL, C, Java (You mathematically tell the computer *how* to loop and retrieve data).
- 4th Gen: Natural, SQL (You tell the computer *what* data you want; the engine figures out how to get it).

Natural was built specifically as the programming interface for **Adabas**, an incredibly fast, non-relational inverted-list database (a precursor to modern NoSQL). In COBOL, writing a program to read a database file, format a screen for a user terminal (CICS), and print a report took 1,000 lines of mathematically verbose code. In Natural, the exact same task took 10 lines of highly readable, English-like syntax.

## 1. Deep Dive & Mechanics

Natural is defined by its **Implicit Database Looping and Integrated Screen Maps**.

In a 3GL like Java, if you want to find all employees in New York, you write a SQL string, execute it, open a mathematical Cursor, write a `while(cursor.next())` loop, and extract variables one by one.

In Natural, the database access is fused directly into the language syntax. You write `FIND EMPLOYEE WITH CITY = 'NEW YORK'`. Natural mathematically infers the database connection, automatically opens the cursor, fetches the data directly into your variables, and creates a hidden loop. Any code written directly below the `FIND` statement executes once per record found, entirely masking the mathematical complexity from the developer.

## 2. Mathematical / Theoretical Foundation

Natural relies on **Inverted-List Database Theory (Adabas)**.

Unlike a Relational Database (SQL) which stores data in rigid rows and columns, Adabas stores data in an **Inverted List**. 
Mathematically, this means Adabas acts like the index of a book. Instead of scanning every page (row) to find the word "Apple", it looks at the "Apple" index, which contains a mathematical array of every physical block on the hard drive where "Apple" exists. 

Natural's syntax was specifically designed to exploit this mathematical structure. Its `READ` and `FIND` statements allow the language to jump directly to specific physical disk blocks in milliseconds, making Natural/Adabas applications mathematically capable of handling massive transactional throughput on 1980s mainframe hardware.

## 3. Real-World Implementation

Here is an example demonstrating a complete Natural program. It queries a database, calculates a bonus, and prints a report. Notice how there is no explicit database connection setup and no explicit cursor looping—it is entirely abstracted away.

```natural
* 1. Comment Line
* A Natural program is usually divided into Data Definitions and Processing.

* 2. Data Definition
* Similar to COBOL, we define the mathematical shape of our variables.
* (A20) = Alphanumeric 20 bytes. (N7.2) = Numeric 7 digits, 2 decimal places.
DEFINE DATA LOCAL
1 EMPLOYEES VIEW OF EMPLOYEES-DB  /* Maps exactly to the Adabas database schema
  2 PERSONNEL-ID      (A8)
  2 FIRST-NAME        (A20)
  2 LAST-NAME         (A20)
  2 SALARY            (N7.2)
  2 BONUS             (N7.2)
1 #MIN-SALARY         (N7.2) INIT <50000.00>
1 #CALC-BONUS         (N7.2)
END-DEFINE

* 3. Processing Logic
* The READ LOGICAL statement automatically initiates a database cursor loop.
* It reads the Adabas database in alphabetical order by LAST-NAME.
READ LOGICAL EMPLOYEES BY LAST-NAME STARTING FROM 'A'
  
  * 4. Conditional Math
  IF SALARY >= #MIN-SALARY THEN
    * Calculate a 10% mathematical bonus
    COMPUTE #CALC-BONUS = SALARY * 0.10
  ELSE
    * Calculate a flat 5% mathematical bonus
    COMPUTE #CALC-BONUS = SALARY * 0.05
  END-IF
  
  * 5. Database Update
  * We assign the local mathematical calculation to the database view variable
  ASSIGN BONUS = #CALC-BONUS
  
  * UPDATE applies the change mathematically to the current row in Adabas
  UPDATE
  
  * 6. Output (Screen / Printer)
  * DISPLAY automatically formats a beautiful table on the mainframe terminal screen,
  * automatically generating column headers based on the variable names.
  DISPLAY PERSONNEL-ID FIRST-NAME LAST-NAME SALARY BONUS
  
* The END-READ mathematically closes the cursor loop initiated by the READ statement.
END-READ

* END OF TRANSACTION commits the database updates physically to the Adabas log.
END TRANSACTION
END
```

## 5. Interview Prep

**Q: What is a 4GL (Fourth-Generation Language)?**
**A:** A 3GL (like C or Java) requires the programmer to mathematically dictate the control flow (`for i=0; i<length; i++`). A 4GL (like Natural or SQL) abstracts the control flow away. The programmer focuses entirely on the business logic (`FIND ALL X`). The 4GL compiler mathematically generates the underlying loops and memory management, dramatically increasing developer productivity at the cost of low-level CPU control.

**Q: Why was Natural often chosen over COBOL?**
**A:** Speed of development. In 1985, if a bank needed a new screen allowing a teller to query a customer's balance, a COBOL programmer would take two weeks to write the CICS screen maps, the DB2 SQL queries, and the backend logic. A Natural programmer could write the same program in a single afternoon because Natural mathematically generated the screen maps (`INPUT`) and handled the database cursors (`READ`) automatically.

**Q: Does anyone still use Natural?**
**A:** Yes. Massive government agencies (like state DMV systems, tax authorities, and police databases) and large insurance companies built their entire enterprise infrastructure on Natural/Adabas in the 1980s. Because the Adabas inverted-list database is mathematically so incredibly fast at text-searching, many of these organizations refuse to migrate to modern relational databases (like Oracle), choosing instead to maintain their Natural codebases.

## 6. Production Use Cases

Natural is deeply entrenched in legacy government, university, and insurance mainframes:
- **State Governments and DMVs:** Many US State Departments of Motor Vehicles still run on Natural. When a police officer pulls you over and runs your license plate, the query often hits a mainframe running a Natural program. The program uses Adabas's inverted-list index to mathematically search 50 million vehicle records by license plate number and return the result to the officer's terminal in less than a second.
- **University Administration Systems:** In the 1980s and 90s, hundreds of major universities bought a massive software package called *Banner* (originally written in COBOL and heavily customized with Natural). These systems handle student registration, grades, and financial aid. When 20,000 students try to register for classes simultaneously on registration day, Natural/Adabas handles the massive mathematical concurrency spikes flawlessly.
- **Insurance Policy Management:** Massive insurance companies (like Allianz) process millions of claims daily. Their core policy management systems are written in Natural. Natural's built-in mathematical decimal precision handles the complex financial actuarial math, while the implicit Adabas integration allows the system to rapidly search through 30 years of historical claims data to detect fraud patterns.

<Callout icon="warning" title="The Modernization Dilemma">
Because Natural abstracts so much of the underlying architecture (the implicit loops and screen generations), it is mathematically incredibly difficult to translate Natural code automatically into modern Java or C#. When a corporation decides to migrate off the mainframe, they cannot just run a translation tool; they often have to completely mathematically re-engineer the entire application architecture from scratch.
</Callout>
