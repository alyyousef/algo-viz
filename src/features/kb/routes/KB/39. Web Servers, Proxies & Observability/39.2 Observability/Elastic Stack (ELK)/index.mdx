The **Elastic Stack** (still called ELK: Elasticsearch, Logstash, Kibana, plus Beats) is how many teams first centralized logs. **Elasticsearch** indexes tokens so a query like `status:500 AND user:42` returns in milliseconds across billions of lines. That index is why it feels magical — and why the cluster eats heap and SSDs.

## 1. Deep Dive and Mechanics

**Ship.** Filebeat or Elastic Agent tails files or journald on each node. It checkpoints byte offsets and forwards to Elasticsearch (or to Logstash / Kafka first).

**Parse.** Ingest pipelines or Logstash filters grok a line into fields (`status`, `path`, `latency_ms`). Structured JSON from the app skips most grok pain.

**Index.** Elasticsearch stores documents in **inverted indexes** per field, sharded across nodes. Index Lifecycle Management (ILM) rolls hot → warm → cold → delete. Hot data lives on fast disks; old indices shrink or snapshot to object storage.

**Kibana.** Discover, Lens dashboards, alerting, and (in paid tiers) SIEM. Humans never SSH-and-grep except when the cluster is down — which is when you need logs most. Keep an escape hatch (S3 copies).

**ELK versus Elastic Observability.** The company now ships APM and metrics too. Classic “ELK” still means logs-first.

<Callout icon="warning" title="Index everything is a cost strategy, not a logging strategy">
Mapping explosion (a new field per user-agent variant) and unbounded retention are how ELK outgrows the product budget. Cap fields, drop debug in prod, and set ILM before the first incident.
</Callout>

## 2. Mathematical / Theoretical Foundation

An inverted index maps term → posting list of document ids. Query time is roughly proportional to the length of those lists plus scoring, not to the raw log volume on disk — **if** the terms are selective. A query for `error` on an index of only errors is a full scan in disguise.

Heap: Lucene segment memory plus JVM. A common planning number is tens of GB of heap per hot node, never more than about half of RAM, and never above ~30 GB (compressed oops). Storage is a multiple of raw JSON because of inverted indexes, doc values, and replicas (factor often 1.5× to 3× before compression tricks).

## 3. Real-World Implementation

```yaml
# filebeat.yml
filebeat.inputs:
  - type: filestream
    id: app
    paths:
      - /var/log/app/*.log
    parsers:
      - ndjson:
          keys_under_root: true

output.elasticsearch:
  hosts: ["https://es.internal:9200"]
  username: filebeat
  password: ${FILEBEAT_PASSWORD}
```

Prefer NDJSON from the app so Filebeat does not grok. The password belongs in an env var or secret, not in git.

## 5. Interview Prep

**Q: Why is Elasticsearch so much more expensive than Loki?**
**A:** Loki indexes labels and greps the rest. Elasticsearch indexes terms in the body. You pay RAM and SSD for arbitrary full-text. That is the right trade if analysts live in ad-hoc queries.

**Q: What is a mapping explosion?**
**A:** Dynamic mapping creates a new field for every JSON key. One log line with a unique payload shape can create thousands of fields and melt the cluster state.

**Q: Hot-warm-cold?**
**A:** Time-based indices move to cheaper hardware as they age. Queries over 90 days hit cold nodes and are slow — by design.

## 6. Production Use Cases

- **Security and audit** search where “find this token across six weeks” is a weekly job.
- **Product analytics on logs** (with a real pipeline and field discipline).
- **Legacy estates** already staffed with Kibana muscle memory.

<Callout icon="tip" title="Snapshot before you need a restore">
ILM delete without snapshots is not a retention policy. Test a restore to a scratch cluster once a quarter.
</Callout>
