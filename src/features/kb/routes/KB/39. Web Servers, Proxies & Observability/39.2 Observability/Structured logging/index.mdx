Historically, developers wrote logs as unstructured text: `log.info("User 456 failed to login from IP 10.0.0.1")`.
To search for all failed logins from a specific subnet, an engineer had to write complex, fragile Regular Expressions. If a developer changed the log string to "Login failed for User 456", the Regex mathematically broke.

## 1. The JSON Mandate
Structured logging solves this by enforcing a mathematical rule: **Logs must be key-value pairs (usually JSON).**
Instead of a string, the developer writes:
```javascript
logger.info("login_failed", {
  user_id: 456,
  ip_address: "10.0.0.1",
  reason: "invalid_password"
});
```

## 2. Instant Mathematical Indexing
When this JSON log hits Elasticsearch or Datadog, the database mathematically recognizes the keys. It instantly creates an index for `user_id` and `ip_address`.
An engineer can now write a strict mathematical query: `SELECT count(*) FROM logs WHERE reason = 'invalid_password' AND ip_address = '10.0.0.1'`. The search returns instantly, without requiring any complex string parsing, making structured logging an absolute requirement for modern distributed systems.
