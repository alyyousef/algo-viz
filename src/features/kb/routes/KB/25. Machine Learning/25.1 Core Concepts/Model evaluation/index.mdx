Before deploying a Machine Learning model into production, you must rigorously quantify its performance. The metrics you choose depend entirely on whether the task is **Regression** (predicting a continuous number) or **Classification** (predicting a discrete label).

## 1. Regression Metrics

When predicting numbers (like house prices), you measure the distance between the predicted number ($\hat{y}$) and the true number ($y$).

## 2. Classification Metrics

When predicting categories, simple Accuracy is often deeply misleading, especially if the data is imbalanced (e.g., 99% healthy patients, 1% sick patients).

- **Precision:** Out of all the positive predictions the model made, how many were actually positive?
- **Recall (Sensitivity):** Out of all the actual positives in reality, how many did the model find?
- **F1-Score:** The Harmonic Mean of Precision and Recall. Used when you need a single metric to balance the two.

### The ROC Curve & AUC

Most classification models don't actually output "Spam" or "Not Spam". They output a probability (e.g., "0.87 chance of Spam"). 
By default, we set a **Threshold** of 0.5. If probability > 0.5, it's Spam.

The **Receiver Operating Characteristic (ROC)** curve plots the True Positive Rate against the False Positive Rate across *every possible threshold* (from 0.0 to 1.0). 
The **Area Under the Curve (AUC)** gives a single number (from 0.5 to 1.0) describing how well the model separates the two classes, regardless of the threshold chosen. 

<Callout icon="lightbulb" title="Moving the Threshold">
In medical diagnoses (where missing a cancer case is fatal, but a false positive just requires another blood test), you want extremely high Recall. You achieve this by lowering the decision threshold from 0.5 down to 0.1. The model will flag almost everyone, catching 100% of the cancers, but causing many false alarms.
</Callout>
