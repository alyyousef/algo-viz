In Machine Learning, there are two types of parameters:
- **Model Parameters:** Things the model learns on its own from the data (e.g., the weights and biases in a neural network, or the split points in a decision tree). You do *not* set these.
- **Hyperparameters:** The architectural settings you must define *before* training begins (e.g., the learning rate, the maximum depth of a tree, or the number of clusters $K$ in K-Means).

**Hyperparameter Optimization (Tuning)** is the tedious but necessary process of finding the exact combination of hyperparameters that minimizes the loss function.

## 1. Grid Search

The simplest, most brute-force approach.
You give the algorithm a list of values to try for each hyperparameter. 
- `max_depth = [3, 5, 10]`
- `learning_rate = [0.01, 0.1, 0.5]`
- `n_estimators = [100, 500]`

The algorithm will train a separate model for *every single possible combination* of these values ($3 \times 3 \times 2 = 18$ models). It evaluates them all using Cross-Validation and returns the best one.
- **Pros:** Guaranteed to find the best combination out of the options provided.
- **Cons:** Computationally horrific. It suffers from the combinatorial explosion. If you add just a few more parameters, you might need to train 10,000 models.

## 2. Random Search

Instead of trying every possible combination, you define a statistical distribution for each hyperparameter, and the algorithm randomly samples combinations for a set number of iterations (e.g., 50 times).

Surprisingly, **Random Search almost always outperforms Grid Search** in a fraction of the time. 
Why? Because in any given model, only 1 or 2 hyperparameters actually matter. Grid Search wastes 90% of its time meticulously tweaking useless parameters. Random Search explores the "important" parameter space much more effectively.

## 3. Bayesian Optimization

Both Grid and Random Search are "dumb" — they don't learn from their past mistakes. If iteration #1 is terrible, iteration #2 might accidentally guess parameters right next to iteration #1.

Bayesian Optimization uses a surrogate model (usually a Gaussian Process) to keep track of past evaluation results. It uses probability to answer the question: *"Based on the models I have already trained, which hyperparameter combination is most likely to yield a better result than my current best?"*

- **Pros:** Highly efficient. It hones in on the optimal parameters in very few steps.
- **Cons:** Complex to implement (though libraries like Optuna make it easy).

<Callout icon="warning" title="The Overfitting Trap">
If you run Hyperparameter Optimization across thousands of combinations and pick the one with the highest Cross-Validation score on your training set, you have essentially leaked data. You have overfit your *hyperparameters* to the validation set. This is why you must always have a completely untouched, hidden **Holdout Test Set** to evaluate the final tuned model.
</Callout>
