In Machine Learning, if you train your model on a dataset and then test it on that *exact same* dataset, it will look like a genius (achieving near 100% accuracy). However, when deployed to the real world, it will fail miserably. This is because the model just memorized the answers instead of learning the underlying patterns.

To prevent this, we must always test a model on data it has never seen. 
The simplest way is a **Train-Test Split**: randomly split the data into 80% for training and 20% for testing. 

However, a simple split is risky. What if, by pure chance, all the difficult examples ended up in the Test set? The model would look artificially terrible. What if all the easy examples ended up in the Test set? The model would look artificially amazing. 

**Cross-Validation** solves this by rotating the test set.

## K-Fold Cross-Validation

The standard gold standard for evaluating model performance.

1. **Shuffle:** Randomly shuffle the entire dataset.
2. **Split:** Divide the dataset into $K$ equal-sized chunks (called "folds"). Usually, $K = 5$ or $K = 10$.
3. **Iterate:** Train the model $K$ separate times.
   - On Iteration 1: Use Fold 1 as the Test set, and Folds 2-5 as the Training set.
   - On Iteration 2: Use Fold 2 as the Test set, and Folds 1, 3-5 as the Training set.
   - ...and so on.
4. **Average:** You now have $K$ different performance scores. Average them together to get the final, highly robust estimate of the model's true performance.

By doing this, *every single data point* gets to be in the test set exactly once, and gets to be in the training set $K-1$ times. The variance in the score is minimized.

## Stratified K-Fold

Used for classification problems with imbalanced data. 
If your dataset is 90% dogs and 10% cats, a random K-Fold split might accidentally create a fold that contains 100% dogs and 0% cats. 

**Stratified K-Fold** ensures that the ratio of the target variable (90/10) is perfectly preserved inside every single fold, ensuring the model always has a representative sample to train and test on.

## Leave-One-Out Cross-Validation (LOOCV)

The extreme version of K-Fold. If you have 1,000 data points, $K = 1000$. 
The model trains on 999 points and tests on 1 point. It repeats this 1,000 times.

- **Pros:** Maximum possible use of training data.
- **Cons:** Computationally horrific. It requires training the model 1,000 times from scratch. Only used on very tiny, critical datasets (like medical trials with $n=30$ patients).

<Callout icon="warning" title="Data Leakage in Cross-Validation">
A very common mistake by junior data scientists is performing Feature Engineering (like imputing missing values with the dataset mean, or normalizing variables) *before* doing the Cross-Validation split. 
By calculating the mean across the *entire* dataset, information from the future "Test" folds has leaked into the "Training" folds. You must do the K-Fold split *first*, and calculate the mean strictly on the training folds.
</Callout>
