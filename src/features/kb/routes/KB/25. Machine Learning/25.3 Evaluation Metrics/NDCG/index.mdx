**NDCG** (Normalized Discounted Cumulative Gain) is a highly specialized evaluation metric designed specifically for **Information Retrieval** (search engines) and **Recommender Systems**.

If a user searches for "best action movies," a search engine returns a ranked list of results. Metrics like Precision simply ask "How many of these movies are actually action movies?" 

NDCG asks a much more complex, realistic question: **"Are the most highly relevant movies at the very top of the list, and are the mildly relevant movies pushed further down?"**

## How NDCG Works (Step-by-Step)

NDCG is built up in three stages.

### 1. Cumulative Gain (CG)
First, every document in your dataset must be assigned a **relevance score** (usually by human raters). 
For example: 3 (Highly Relevant), 2 (Relevant), 1 (Marginally Relevant), 0 (Not Relevant).

The Cumulative Gain is simply the sum of the relevance scores of the top $p$ results returned by the model.
If the top 3 results have relevance scores of [3, 0, 2], the CG@3 is $3 + 0 + 2 = 5$.

*Flaw:* CG doesn't care about order. A model returning [3, 0, 2] gets the same CG as a model returning [0, 2, 3]. But putting the highly relevant item at the bottom is a much worse user experience.

### 2. Discounted Cumulative Gain (DCG)
DCG fixes the order problem by applying a **logarithmic discount**. The further down the list a relevant document appears, the less its relevance score contributes to the total.

The formula divides the relevance score by the logarithm of its rank position:

$$\text{DCG}_p = \sum_{i=1}^{p} \frac{rel_i}{\log_2(i + 1)}$$

*   Rank 1: Relevance / $\log_2(2)$ = Relevance / 1 (No discount)
*   Rank 2: Relevance / $\log_2(3)$ = Relevance / 1.58 (Moderate discount)
*   Rank 10: Relevance / $\log_2(11)$ = Relevance / 3.45 (Heavy discount)

Now, putting the "3" score at rank 1 yields a much higher DCG than putting it at rank 10.

### 3. Normalized Discounted Cumulative Gain (NDCG)
Search queries vary wildly. A query for "Star Wars movies" might have 11 highly relevant results in the database. A query for "1994 obscure indie sci-fi" might only have 1 relevant result. 
Because of this, DCG scores vary wildly between different queries, making it impossible to average them together to evaluate the overall model.

We need to **normalize** the score between 0.0 and 1.0.

To do this, we calculate the **Ideal DCG (IDCG)**. The IDCG is the DCG score you would get if the model perfectly sorted the results (e.g., [3, 3, 2, 1, 0, 0]).

Finally:
$$\text{NDCG}_p = \frac{\text{DCG}_p}{\text{IDCG}_p}$$

## Summary

NDCG is the gold standard for ranking evaluation because it elegantly handles two critical realities of search and recommendation:
1.  Relevance is not binary (Yes/No); it exists on a graded scale.
2.  Users rarely look past the first few results, so relevant items must be heavily penalized if they are pushed down the list.
