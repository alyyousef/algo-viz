**ONNX (Open Neural Network Exchange)** is not a framework for training models; it is an open standard format for *representing* and *storing* machine learning models. 

Created by Microsoft and Facebook (Meta) in 2017, ONNX was designed to solve a massive interoperability problem in the AI ecosystem.

## The Interoperability Problem

Before ONNX, if you trained a model in PyTorch, it was locked into the PyTorch ecosystem. If you wanted to run that model on a smartphone (which might use CoreML or a specialized Qualcomm inference engine), you had to manually rebuild and translate the entire model into the new framework. 

This resulted in massive engineering overhead, as teams had to maintain different versions of the exact same model for PyTorch, TensorFlow, Scikit-Learn, and various hardware accelerators.

## How ONNX Works

ONNX acts as a universal translator. It defines a common set of operators (like matrix multiplication, convolutions, and activation functions) and a standard file format (usually `.onnx`).

1.  **Export:** You train your model in your favorite framework (e.g., PyTorch). When you are finished, you use a built-in exporter to translate the PyTorch model into an ONNX file.
2.  **Inference:** You take that `.onnx` file and load it into a completely different framework or runtime environment to generate predictions.

### ONNX Runtime

While ONNX is just a file format, Microsoft also built **ONNX Runtime (ORT)**. This is a highly optimized inference engine designed specifically to run `.onnx` files as fast as physically possible.

It automatically detects the hardware it is running on (Intel CPU, NVIDIA GPU, Apple Silicon, edge devices) and applies specific graph optimizations and hardware accelerations to run the model blazingly fast.

<Callout icon="bolt" title="The Standard for Production">
Today, ONNX is the undisputed standard for deploying models to production. A very common modern workflow is: Train in PyTorch -> Export to ONNX -> Deploy to a server using ONNX Runtime for maximum speed and minimal memory overhead.
</Callout>

## Summary

ONNX decoupled the *training* phase of machine learning from the *deployment* phase. It allows researchers to use whatever framework they prefer (usually PyTorch) without worrying about how the engineering team will eventually run the model in the real world.
